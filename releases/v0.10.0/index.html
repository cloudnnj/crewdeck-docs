Release v0.10.0

Release Date: February 5, 2026

Summary​

Version 0.10.0 is a major performance and infrastructure release that dramatically improves terminal rendering speed, system resource management, and task workflow capabilities. This release introduces GPU-accelerated terminal rendering via WebGL, RAF-based output batching for smooth 60 FPS output, intelligent viewport-aware session prioritization, comprehensive performance instrumentation dashboards, and event sourcing architecture for full state change auditing. The release also adds critical workflow enhancements including task failure logging, automatic worktree cleanup, bidirectional GitHub Issue synchronization, context-driven task development, and AI-generated daily activity summaries. Additionally, the release includes 10 bug fixes addressing terminal display issues, dashboard analytics accuracy, and configuration defaults.

Features​

Terminal & Performance​

  • RAF-Based Terminal Output Batching — requestAnimationFrame-based output batching with visibility detection for hidden tabs, reducing CPU usage during background terminal operation
  • Viewport-Aware Session Prioritization — Background terminals buffer aggressively (150ms intervals) while visible terminals get immediate processing (16ms/60 FPS) for optimal responsiveness
  • Pause/Resume Output Control — Manual pause/resume for terminal sessions with buffering capability, enforcing 500KB buffer limits to prevent memory growth
  • Performance Instrumentation Dashboard — Real-time metrics for PTY latency, IPC latency, event loop lag (50ms threshold), and render time with historical charting
  • System Health Monitoring — CPU/memory health gate preventing session creation when system is overloaded (95% CPU or critical memory pressure)
  • WebGL Terminal Renderer — GPU-accelerated terminal rendering using @xterm/addon-webgl with automatic fallback to Canvas on context loss
  • Event Loop Lag Reduction — Reduced main process event loop lag below 50ms threshold via async file I/O, deferred event sourcing writes, and timer jitter
  • Event Sourcing Architecture — Immutable event log capturing all state changes in state_events table with 180-day retention and 50K event limit

Task Management​

  • Task Failure Logging — Mark tasks as failed from kanban board with optional task recreation, tracking failures in outcome system for analytics
  • Worktree Cleanup on Task Rating — Automatic worktree folder removal after task completion rating via git worktree remove to reclaim disk space
  • Context-Driven Task Development — Copy context repo files (docs, DEPARTMENTS.md) into worktree .crewdeck-context/ folder for agent access without prompt size limits

Repository & Configuration​

  • New Project Onboarding — Auto-copy 6 core commands (create-pr, do-release, improve-pr, refine-prompt, review-pr, document-pr) and project-appropriate leader agent when creating new repositories
  • DEPARTMENTS.md v1.2 Update — Comprehensive documentation update reflecting current codebase state with 91 system prompts, event sourcing, performance dashboard, and telemetry
  • README.md Update — Updated to reflect current services (28 commands, agent-performance-analytics, agent-ranking, feedback, performance-metrics, telemetry), components, and features
  • User Guide Update — Revised user documentation covering agent execution modes (sequential/swarm), dashboard analytics, agent performance dashboard, agent ranking, pause/resume controls, system health monitoring, failure logging, and document workflow

GitHub Integration​

  • Automatic PR Comments — Structured GitHub PR comments summarizing agent activity, execution phases, key decisions, command chain progress, and timing data on task completion
  • Bidirectional GitHub Issue Synchronization — Two-way sync between CrewDeck tasks and GitHub Issues with status mapping (todo ↔ crewdeck:todo label), 60-second polling for merge detection, and conflict resolution

AI & Execution​

  • AI-Generated Daily Activity Summary — Project activity summaries via Ollama LLM with optional Slack delivery, aggregating task outcomes, PR merges, agent performance, and command usage
  • System Prompts Inventory — Comprehensive documentation of all 91 prompt artifacts (10 hardcoded service prompts, 28 command templates, 32 agent definitions, 15 skills, 6 content generation templates)
  • Default Swarm Execution Mode — Multi-agent tasks (2+ agents) default to swarm mode (orchestrated parallel) instead of sequential

UI/UX​

  • Delete Project from UI — Project deletion with typed name confirmation and cascade data removal for repos, agents, commands, tasks, and releases

Bug Fixes​

Dashboard & Analytics​

  • Fixed PR merge rate always showing zero in dashboard analytics — Implemented PR merge tracking via useTaskPrPolling hook with 60-second polling and recordPrMerge IPC channel

Terminal Issues​

  • Fixed terminal tab not rendering output when opened from task — Removed obsolete appendOutput usage in useTerminalLauncher hook to match virtualized terminal architecture
  • Fixed terminal non-responsive when launched from task card modal — Auto-close ViewTaskModal when opening terminal to prevent z-index event capture conflict
  • Fixed terminal displaying setup commands briefly before clearing — Added ANSI escape sequences (\x1b[2J\x1b[H) to clear screen before sending cd and history -c commands
  • Fixed interactive terminal showing garbled characters on launch — Frontend-initiated screen clear after xterm initialization eliminates race condition with PTY data buffering
  • Fixed terminal opening in root directory instead of worktree folder — Force fresh PTY spawn for interactive sessions on cwd mismatch, bypassing pool's unreliable cd command approach

Performance​

  • Fixed performance dashboard displaying excessive zero-latency records in Pipeline Latency chart — Filter snapshots with empty pipelineMetrics from display and historical accumulation
  • Fixed verbose OutputStore memory trimming log messages creating console noise — Removed frequent "[OutputStore] Trimmed X bytes" log that fired on every buffer trim

Task & Configuration​

  • Fixed "Read from Context Repos" flag missing in View/Edit Task modals — Added useContextRepos display (view mode) and toggle (edit mode) matching CreateTaskModal pattern
  • Fixed first repo connected to project defaulting to context instead of primary — Auto-detect first-repo scenarios in repos:connect and github:create-repo handlers, setting repoType: 'primary' and isPrimary: true

Breaking Changes​

None
