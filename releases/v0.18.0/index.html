Release v0.18.0

Release Date: March 15, 2026

Summary​

Version 0.18.0 is the largest and most wide-ranging release in CrewDeck history, shipping approximately 350 features and 219 bug fixes across every layer of the platform. The release is organized around five major investment themes. First, AI intelligence and agent quality: thinking levels, cross-task learning, intelligent agent selection, failure pattern detection, natural language task creation, and auto-task decomposition from epics via a DAG engine bring context-aware AI behavior to the full task lifecycle. Second, terminal performance and architecture: a virtualized row-windowed renderer, WebGL GPU acceleration, worker-thread PTY management via MessagePort, LZ4 ring-buffer compression, proactive memory compaction, adaptive batch sizing, a global RAF frame budget coordinator, and visibility-gated writes deliver a dramatic reduction in memory footprint and CPU usage at high session counts. Third, task workflow depth: task dependencies with a visual DAG graph, epics, team execution mode (Claude Code agent teams), command discovery and chaining, bidirectional GitHub Issue sync, execution replay, a searchable decision journal, and a git-based team collaboration model extend the Kanban board into a full project-level workflow engine. Fourth, security hardening: replacement of --dangerously-skip-permissions with the Claude Code permission hook, command injection fixes, security audit logging infrastructure, CSP hardening, credential access controls, and npm vulnerability remediation address every outstanding security advisory. Fifth, observability and platform health: event sourcing for state changes, tool telemetry, system health monitoring with session spawn gating, performance instrumentation, error logging for AI analysis, and an Electron upgrade from 35 to 38 (Chromium 140, Node.js 22.22.0) complete the platform modernization.

Features​

AI Thinking & Planning​

  • Thinking level selection — Tasks can now specify one of three extended thinking levels (think, think harder, ultrathink). When a level is selected, the service prepends the corresponding keyword instruction to the prompt before execution; the default (no selection) is unchanged
  • Planning mode improvements — Planning mode invocations generate structured, multi-step implementation plans via an extended prompt refinement pass rather than brief summaries; the planning mode toggle is now visible and editable in both the View and Edit Task modals
  • Cross-task learning service — CrossTaskLearningService extracts structured patterns (agent configuration, command sequence, error resolutions, key decisions) from completed tasks, stores them linked to the taskEmbeddings table, and injects the top-3 most relevant historical learnings into new task execution prompts via the existing ContextAggregationService pipeline; a feature flag and injection-tracking in taskOutcomes enable impact measurement

Intelligent Agent & Task Management​

  • Intelligent agent selection with confidence scoring — Agent recommendations now use a composite 60/40 scoring formula combining AgentRankingService historical rank with TaskIntelligenceService embedding similarity, with a 15% boost for user-override signals; a three-tier fallback ensures offline scenarios still produce recommendations
  • Natural language task creation — A "Create from Description" mode in CreateTaskModal sends a free-form English description to TaskIntelligenceService, calls the Claude CLI to extract structured fields (title, description, acceptance criteria, agent names, complexity, priority), and pre-fills the form for user review; a 5-second timeout falls back to manual entry gracefully
  • Auto-task decomposition from epics — An "Auto-decompose" action on epic tasks uses Claude CLI with few-shot examples from CrossTaskLearningService to generate subtask breakdowns with dependency relationships and confidence scores; a review modal lets users edit, remove, or reorder before creation; created subtasks link via the task_dependencies table; quality feedback is stored for continuous improvement
  • Intelligent dependency generation — Dependencies between AI-generated tasks are now determined by the AI at generation time based on logical relationships rather than hard-coded sequential chaining in the frontend; parallel tasks are scheduled in parallel
  • Failure pattern detection with retry suggestions — When a task fails, the service analyzes agentTraces and taskOutcomes to classify the failure pattern (timeout, dependency error, agent-task mismatch, resource exhaustion, permission error) and surfaces actionable retry suggestions with confidence scores; successful recoveries are stored to improve future suggestions

Task Workflow & Dependencies​

  • Task dependencies — Users can declare that task B depends on task A, blocking B from moving to In Progress until A is Done; dependencies are visible as a full list in the View/Edit Task modals and as a compact badge count on Kanban task cards; AI-generated task batches produce dependency links automatically
  • Visual DAG workflow graph — A directed acyclic graph view renders the dependency network for a project's tasks, showing which tasks are blocked, ready, or complete; viewport-gated rendering ensures the graph only updates when visible
  • Epics — Tasks can be grouped under an epic for coordinated delivery tracking; the epic dropdown is available in Create, Edit, and View Task modals; AI task generation populates epic assignments automatically
  • Task card enhancements — Task cards display dependency badge counts, epic labels, thinking level indicators, and execution mode badges directly on the Kanban board
  • Execution replay service — ExecutionReplayService captures complete execution traces (terminal output snapshots, agent trace decisions, command step transitions) into a task_execution_snapshots table; three IPC channels (replay:getSnapshot, replay:listByTask, replay:compareExecutions) enable side-by-side diffs of two executions of the same task
  • Context-driven task development — Task execution now incorporates context repository content into the prompt enrichment pipeline via the existing ContextAggregationService, giving agents visibility into related codebases during execution

Terminal Performance & Architecture​

  • Virtualized terminal rendering with row windowing — Terminal rendering is replaced with a virtualized system that maintains only visible rows plus a configurable buffer; a ring buffer pattern bounds memory to a fixed maximum per session regardless of session duration
  • WebGL GPU-accelerated renderer — @xterm/addon-webgl replaces the Canvas renderer; a lifecycle manager handles WebGL context loss/restore events with automatic Canvas fallback; WebGL auto-promotion activates when 5+ sessions are active
  • Worker-thread PTY management via MessagePort — PTY I/O moves off the main thread into a dedicated worker via PtyWorkerManager; MessagePortManager provides direct MessagePort channels for terminal output streaming, bypassing IPC serialization overhead
  • LZ4 ring buffer compression — Cold-zone ring buffer rows (older than the most recent 2,000 entries) are compressed in 4KB LZ4 blocks for approximately 80% memory savings; hot-zone rows remain uncompressed for zero-latency access
  • Proactive memory compaction — Sessions backgrounded for more than 30 seconds have their xterm.js instance detached from the DOM, scrollback buffers cleared, and last visible rows cached in a lightweight structure; re-attaching replays content from the ring buffer seamlessly
  • Adaptive batch sizing — The output batcher dynamically adjusts flush intervals between 20ms (low volume) and 50ms (high volume) based on observed throughput, balancing responsiveness and IPC overhead
  • Viewport-aware session priority — Active (visible) session PTY output is flushed synchronously; hidden sessions are deferred via setImmediate(), reducing contention on the event loop
  • Per-frame terminal write cap — A maximum write budget per requestAnimationFrame tick prevents any single session from starving others during burst output
  • Pause/resume output control — Users can pause and resume terminal output per session without killing the PTY; the pause button state is reflected consistently across all session views
  • Performance instrumentation — PerformanceMetricsService tracks event loop lag, heap usage, IPC call rates, and per-session output throughput; metrics are surfaced in a new Performance Dashboard accessible from the system tray
  • System health monitoring with session spawn gating — MemoryMonitorService is extended to track CPU alongside memory; a health gate prevents new session creation when the system is overloaded and explains why with actionable suggestions
  • Predictive pre-buffering — Background terminal sessions pre-buffer incoming data so that switching to a previously hidden session renders instantly
  • V8 GC tuning — Per-process V8 garbage collection flags are configured for terminal workloads, reducing GC pause jitter under sustained output
  • Unix domain socket terminal transport — Optional UDS bypass provides a lower-latency IPC path for terminal data; socketClientService.connect() is deferred until the worker confirms the socket is listening via a socket-ready event

Multi-Agent Execution​

  • Team execution mode — A new "Team" execution mode alongside Sequential and Swarm spawns fully independent Claude Code agent instances that communicate directly via Claude Code's native agent teams feature; a lead agent coordinates teammates via a shared task list and inter-agent messaging
  • Command discovery — .claude/commands/ files are scanned on repo connect and surfaced in a new Commands view (accessible from the top navigation alongside Agents); commands are selectable from a new "Assign Command" picklist in the Create Task modal
  • Command chaining — Multiple commands can be sequenced within a single task execution (e.g., lint then test then build), with each step's output visible as a distinct phase in the terminal panel
  • Interactive Claude terminal sessions — Task execution terminals are fully bidirectional; users can type input to the Claude agent while it is running without leaving the terminal panel
  • Default agent execution type — Projects can specify a default execution type (Sequential, Swarm, Team) that pre-populates the task creation form, reducing repetitive configuration

GitHub & Repository Integration​

  • Bidirectional GitHub Issue synchronization — Tasks linked to GitHub Issues now sync status in both directions: closing a task closes the linked Issue, and closing an Issue in GitHub marks the linked task Done; a polling mechanism (useTaskPrPolling pattern) detects external Issue status changes; users can create Issues from existing tasks or import Issues as tasks
  • Automatic PR comment summaries — AI-generated summaries are posted as comments on Pull Requests automatically after task completion
  • Alternative branch support — Tasks can target a non-default branch as the base for worktree creation, supporting hotfix and feature-branch workflows
  • Worktree cleanup on release — The release workflow now cleans up all stale worktrees associated with the release's tasks before finalizing, preventing worktree accumulation
  • Move Import Issues button — The Import Issues action is relocated from the Board header to the project Actions dropdown for better discoverability

Debate & Decision Journal​

  • Debate screen improvements — The debate wizard gains an elapsed-time timer in the header, a "Send to Background" button that minimizes the modal into a compact notification bar, and CSS animations in the output panel to convey active agent activity
  • Searchable decision journal — Multi-agent debate transcripts are persisted as searchable decision records using SQLite FTS5; a journal UI on the Project page supports filtering by date, topic, status, and participating agents, with full-text search across titles, descriptions, and transcript content

Security Hardening​

  • Replace --dangerously-skip-permissions with Claude Code permission hook — All task execution and debate execution paths now use @abdo-el-mobayad/claude-code-fast-permission-hook for a three-tier permission system (fast approve, fast deny, LLM analysis) instead of the broad --dangerously-skip-permissions flag
  • Fix command injection in PermissionHookService — All child_process.exec() calls replaced with execFile() via the existing shellExec() utility, eliminating shell injection via argument strings
  • Security audit logging infrastructure — SecurityAuditService captures all security-relevant events (IPC calls, command executions, credential access, agent actions) with structured logging to a separate SQLite database; tamper-evident timestamps, automatic log rotation, and configurable retention policies are included
  • Credential access controls — CredentialAccessControlService enforces per-service rate limits and access logging on all SecureStorageService calls, preventing unauthorized bulk credential reads
  • npm vulnerability remediation — All 17 vulnerabilities (5 high, 12 moderate) reported by npm audit and Dependabot affecting electron-builder, tar, esbuild, vite, vitest, drizzle-kit, electron-vite, and lodash are resolved

Event Sourcing & Observability​

  • Event sourcing architecture — A state_events table captures all task and agent state mutations as immutable event records, providing the foundation for audit trails, undo/redo, and future sync capabilities
  • Tool telemetry — MCP tool invocations and Claude Code tool calls are tracked via TelemetryService with structured call metadata, enabling analysis of which tools agents use most frequently
  • Error logging for AI analysis — Structured error logs from task execution failures are formatted for consumption by AI analysis pipelines; the FailurePatternDetectionService reads these logs to improve retry suggestions
  • AI-generated daily activity summaries — A daily summary generator aggregates taskOutcomes, agentTraces, and event logs into a human-readable activity digest surfaced on the Project page
  • System prompts registry — A list of all active system prompts used by each agent is accessible from the agent configuration UI, making prompt engineering auditable

Platform & Infrastructure​

  • Electron upgrade from 35 to 38 — The runtime upgrades across three major versions (36, 37, 38), moving from Chromium 134 to 140, Node.js 22.14.0 to 22.22.0, and V8 13.5 to 14.0; Electron 35 had reached end-of-life
  • Decompose TaskExecutionService monolith — task-execution.service.ts is split into focused sub-services (prompt-engineering.service.ts, worktree-lifecycle.service.ts, pr-automation.service.ts) to reduce file size and isolate responsibilities
  • Decompose handlers.ts monolith — electron/ipc/handlers.ts is decomposed into per-domain handler modules following the existing HandlerModule pattern, improving discoverability and reducing merge conflicts
  • Standardized error handling — toErrorMessage() type guard replaces all unsafe (error as Error).message casts across the codebase; the withServiceResult wrapper coverage is extended to all remaining handlers
  • Worker termination acknowledgment protocol — PTY worker threads use an ACK-based termination handshake instead of arbitrary timeouts; SIGKILL fallback handles unresponsive processes; sessionCallbacks are cleared on termination to prevent memory leaks
  • Centralize hardcoded configuration — Magic numbers, timeout values, and feature flags are moved to electron/constants/index.ts and electron/config/ for a single source of truth
  • CI infrastructure — CI setup, teardown, and orphan cleanup scripts are added; a SonarCloud integration research spike is included for future static analysis coverage
  • Users table — A users table is added to support multi-user team mode and future collaboration features

Documentation​

  • Core services documentation — Comprehensive reference documentation for TaskExecutionService, TerminalService, GitHubService, AgentRankingService, and CrossTaskLearningService is generated and committed to docs/design/
  • Database documentation — Schema diagrams, migration guides, and data dictionary entries are generated for the full Drizzle ORM schema
  • User guide updates — The user guide is updated with sections covering all new features: task dependencies, epics, thinking levels, team mode, natural language task creation, the decision journal, and execution replay
  • New department onboarding guide — A structured onboarding document for new project teams is added to docs/

Bug Fixes​

Terminal Output & Rendering​

  • Fixed terminal tab not rendering output — Ring buffer data was cleared before the renderer finished consuming it on PTY exit; the buffer lifecycle is now synchronized with the renderer drain event
  • Fixed terminal alignment issues — PTY dimension mismatch during initial session setup caused visual corruption at narrow widths; PTY is now correctly sized before the first write
  • Fixed text alignment in terminal execution — Overlapping character rendering in the terminal panel execution view is corrected
  • Fixed terminal session not responding after backpressure — When a session entered flow control pause state, user keystrokes were silently discarded; the PTY is now uncorked on user input regardless of outbound backpressure state, breaking the deadlock
  • Fixed terminal scroll jumping to middle — The virtual scroll position was not being clamped correctly on session switch, causing the viewport to jump to an unexpected row
  • Fixed terminal readability bugs — Multiple minor rendering defects (incorrect background color, character clipping at row boundaries, cursor blink interference) are corrected
  • Fixed terminal screen update artifacts — Partial-row updates caused stale character fragments to remain visible after a full-screen repaint; the damaged region is now correctly invalidated
  • Fixed terminal tab scrolling back to top on switch — Switching between terminal tabs no longer resets scroll position to row 0
  • Fixed backpressure terminal session not responding to input — See terminal backpressure fix above

Memory & Resource Management​

  • Fixed memory leak in PTY processes — PTY processes not properly cleaned up on session termination now have explicit disposal paths; all onData closures that captured ring buffers are released when sessions close
  • Fixed stale closure leak in PTY onData callbacks — When a session crashed and was recovered via terminal:recover-session, the previous session's onData closure and its captured TerminalRingBuffer were orphaned; spawnViaWorker now explicitly clears the previous closure before registering a new one
  • Fixed accumulated worker event listener leaks — Worker thread event listeners registered during session creation were not removed on session close, accumulating over the application lifetime
  • Fixed SIGKILL fallback for unresponsive PTY kill — Processes that did not respond to SIGTERM within the timeout window were left as zombies; a SIGKILL fallback with ACK-based confirmation now handles these cases; sessionCallbacks are cleared to prevent reference leaks
  • Fixed event loop lag exceeding 50ms threshold — Blocking operations in the main process (synchronous DB reads, large JSON serialization) are moved off the main thread or batched to keep event loop lag below 50ms

Task Execution & Agent Configuration​

  • Fixed task execution for alternative branch — Tasks targeting a non-default base branch were creating worktrees from the wrong commit; the branch resolution path is corrected
  • Fixed agent execution mode not sticking — The execution mode selection (Sequential/Swarm/Team) was not being persisted on task save; the field is now included in the UpdateTaskSchema Zod validation
  • Fixed team mode terminal freeze — An argument-order bug in executeTeamWorkflow caused all parameters to shift by one position, registering the PTY under key true instead of the session ID; user input could not be routed to the PTY
  • Fixed read-from-context-repo flag — The useContextRepos flag was being dropped from task update payloads because it was absent from UpdateTaskSchema; added alongside epicId, issueUrl, issueNumber, lastSyncedAt, and pausedAt
  • Fixed task card and view not reflecting step execution — Step-level progress indicators in task cards and the task view modal were not updating when command steps transitioned; the step state subscription is now wired correctly
  • Fixed should not execute a task without an agent — Task execution was proceeding when no agent was assigned; a pre-execution guard now blocks execution and surfaces a user-readable error
  • Fixed release action menu executing wrong action — The release action dropdown was triggering the first menu item instead of the selected item due to an event propagation bug; e.stopPropagation() is added to each action button

Debate & Decision Journal​

  • Fixed debates timing out — The debate execution timeout is increased from 20 to 30 minutes to accommodate longer multi-agent document generation runs
  • Fixed debate execution bug — An unhandled rejection in DebateExecutionService when the debate PTY exited with a non-zero code was silently swallowing the error; proper error propagation is now in place
  • Fixed sending debate to background — The "Send to Background" action was not updating the debate status in the store, leaving the modal stale after backgrounding
  • Fixed step execution display not updating — Debate step progress was not reflected in the debate wizard output panel during execution

GitHub & Repository Integration​

  • Fixed importing GitHub issues not working — The import issues pipeline failed when the GitHub API returned paginated responses; pagination is now handled correctly
  • Fixed task with GitHub issue not closing issue on PR merge — The post-merge webhook handler was not finding the linked issue due to a stale task reference; re-fetching from the database after merge resolves the stale closure
  • Fixed cannot refresh primary repo containing uncommitted changes — Refresh was blocking on uncommitted changes; agent/command re-discovery now proceeds regardless of local git state; the pull step is skipped with an informational message if uncommitted changes prevent it
  • Fixed GitHub global rate limit exceeded errors — The in-memory credential cache check now runs before the rate limit counter, so cached credential reads no longer count against the 30-per-minute limit
  • Fixed export action not writing file — The JSON/YAML data export was calling the wrong IPC channel name after the handler decomposition; the channel name is corrected in the preload bridge

Epic Management​

  • Fixed epic generation failure — Tasks generated by the "Generate Tasks" AI workflow were not being linked to the newly created epic due to a missing epicId in the bulk create payload; the epic association is now included
  • Fixed cannot assign epic to a task — Epic assignment was silently dropped on save because epicId was absent from UpdateTaskSchema; the field is now validated and persisted

Security & Secrets​

  • Fixed command injection in PermissionHookService — exec() with shell string replaced by execFile() via shellExec(); argument arrays prevent shell interpolation
  • Fixed false email redaction — The email regex in SecretDetectionService was matching hyphenated package names and other non-email strings; the pattern is tightened to require valid domain structure
  • Fixed wrong redaction output — Redaction was producing malformed output when multiple secret types were detected in the same string; concurrent redaction passes are now applied sequentially
  • Fixed false "redacted 1 secret types" log spam — Non-secret strings matching over-broad patterns were generating spurious redaction log entries on every terminal write

UI & Interaction​

  • Fixed create task modal not displaying — A React rendering error prevented the Create Task modal from opening when no agents were loaded; the guard condition is corrected
  • Fixed during onboarding user cannot proceed — A missing field in the onboarding form submission schema caused the onboarding flow to reject valid entries; the Zod schema is aligned with the form fields
  • Fixed when navigating to project the board is missing — A race condition between project load and board initialization caused the Kanban board to render blank on initial navigation; the initialization order is corrected
  • Fixed infinite re-render on performance dashboard — The performance dashboard triggered a re-render loop due to an unstable selector reference; useShallow with a stable constant is applied
  • Fixed edit state of task resetting — Editing a task field and then switching to another field caused the first field to revert; controlled input state management is corrected
  • Fixed task feedback submission — Submitting a task rating was failing with a validation error because the CreateDecompositionFeedback Zod schema used different field names than the TypeScript interface; field names are now aligned
  • Fixed rate tasks function firing incorrectly — The task rating trigger was firing on status changes unrelated to task completion; the condition is tightened to check the done transition specifically
  • Fixed block user ability to refresh — Accidental page refresh via keyboard shortcut or browser navigation was not blocked correctly in the packaged app; the main-process intercept layer is corrected
  • Fixed push notification link — Push notification click-through links were navigating to the wrong project or task due to a stale project ID in the notification payload; the ID is resolved at notification dispatch time
  • Fixed push notification text — Notification body text was truncated incorrectly for long task titles; the truncation limit is increased and ellipsis is applied correctly
  • Fixed journal entries displaying agent name incorrectly — The decision journal was showing the raw agent identifier instead of the display name; the lookup resolves against the agents store
  • Fixed select/deselect Claude file attachment — Toggling a file attachment selection in the task creation form was not updating the attachment list state correctly
  • Fixed save log button not generating file — The "Save Log" action in the terminal panel was silently failing when the log path contained spaces; the path is quoted correctly in the file write call
  • Fixed cannot add new command to agent — Adding a new slash command to an agent definition via the UI was not persisting because the write path used the wrong file extension

Password & Authentication​

  • Fixed persistent keytar password prompt loop — The macOS keychain prompt loop now fires at most once per app launch; the SecureStorageService request deduplication prevents concurrent redundant keychain lookups from spawning multiple OS dialogs
  • Fixed app asking for password repeatedly in settings — Settings page loads were triggering multiple concurrent credential reads; the reads are batched and deduplicated

Onboarding & Project Management​

  • Fixed project onboarding failing — A missing null check on the primary repo path caused onboarding to crash before completing; the guard is added
  • Fixed when a new department repo is added — Repo addition was not triggering agent/command discovery for multi-repo projects; the discovery pipeline is now called after every successful repo connect
  • Fixed ability to launch interactive terminal on new department — Interactive terminal sessions were not available until after the first task execution in a project; the session infrastructure is now initialized at project creation time

CI & Testing​

  • Fixed CI/CD unit test failures — Several test files were importing modules with mismatched mock configurations after the handler decomposition; mock boundaries are corrected
  • Fixed documentation generation failing — The documentation generation command was failing on projects with deeply nested file structures; path resolution is corrected

Breaking Changes​

None
